## The challenge

For a regulated company, it is not enough for AI to answer. It has to give the same answer every time and prove where each number came from. A probabilistic model cannot guarantee that, and it bills tokens for every question.

## The solution

An ontology in versioned YAML defines each business metric once. For example, "days of inventory" is units on hand divided by average daily sales over 28 days. A deterministic engine compiles that definition to SQL and runs it on DuckDB or BigQuery. The agent, built with LangGraph, uses the LLM only to translate the question, and refuses what the ontology does not define instead of making it up. Lead times are read from supplier emails with Elasticsearch and feed a reorder rule that cites its source. Every answer leaves a record with the ontology version, the formula, the query and the data fingerprint.

## Result

Marginal cost per query tends to zero, so the system scales to any number of users without a token budget. It also runs where the data lives, behind the client's firewall.
